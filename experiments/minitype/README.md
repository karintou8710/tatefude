# minitype 実験

デモの doc を **minitype (組版エンジン) で組んで PDF にする**、ローカル専用のサーバー。
「minitype (実験)」ボタンがここを叩く。

```bash
pnpm dev:minitype   # http://localhost:8787
pnpm dev            # デモ。/api を上のサーバーへ proxy する
```

## 何を見るための実験か

1. **ルビの行送り** — ブラウザはルビのある行だけ行送りを広げる。組版エンジンなら広がらないので、
   文庫どおりの行送りで組めるはず
2. 判型・余白・送りを与えた組みがそのまま出るか
3. 行分割の質 (Knuth–Plass vs ブラウザの貪欲法)
4. 台本の書式 (横罫・柱の番号・人物名の枠) がどこまで移せるか

## 分かったこと (小説, 文庫 105×148mm / 41 字 × 16 行 / 6 ページ)

- 組版は 100〜300ms。ページ数と診断 (overfull-line 等) はサーバーのログに出る
- **余白は spec の値をそのまま置く。**engine の `calculatePhysicalPadding` は行の積み方向に
  半行ぶん少なく取るので、指定した行数より 1 行少なくなる
- **ルビで行送りが崩れない。**だから紙は文庫どおりの 1.71 (13.95pt / 8.15pt) で組める。
  ブラウザ (編集画面) は注記が行間を押し広げるので 2.0 が下限で、そこは合わせていない
- ぶら下げは既定で有効なので切ってある。有効だと行長を 0.5 字ぶん超える
- ノンブルは `Flow` の `position: "nombre"` (版面の下端) + `page`。**書字方向をフローごとに
  変えられる**ので、本文が縦組みのまま数字だけ横組みにできる。
  公式の novel テンプレート (create-minitype) と同じ形で、置き場所も採番もエンジン側にある。
  自前なのは級数・色・版面からの距離だけ
- **縦中横は数字しか組めない。**エンジンの `tatechuyoko` は連続する数字を拾う設定で、
  任意の文字列を 1 字ぶんに組む口が無い。`Tcy("!?")` は 1 字ずつ縦に積まれて画面とずれる。
  桁数の上限も既定の 2 のままにしてある — 3 桁以上は 1 字ぶんに収まらず隣の行に被る
- 台本は**横罫・柱の番号・シーンの間隔が落ちる**。CSS の counter と border で組んだ装飾は
  そのままでは移らない。人物名の枠 (8 字) と字下げだけ `hbox` / `indent` で写してある

## 確かめ方

行数と字数は目で数えると間違えるので、PDF から字の座標を拾って測る。

## 構成

ブラウザは `doc.toJSON()` と組みの数字を投げるだけで、`Group[]` への変換は `convert.ts` が持つ。
**デモ側は minitype に一切触れない** — クライアントのバンドルにも `package.json` にも入らない。
